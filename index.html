01 · 为什么

为什么要做消费记忆？

记账解决的是“记录发生了什么”。真正长期有价值的问题，是消费发生之后，信息有没有被记住、理解和重新调用。

传统记账

记录一笔交易

2026-09-18 · 玩具 → 积木 · ¥199。信息被准确保存，但它仍然只是一个时间切片。

消费记忆

理解一段消费经历

什么时候买的？后来有没有用？是否少用、退货、闲置？这些后续事实可以继续成为用户自己的长期记忆。

“我想知道自己买过什么、花了多少、值不值——不用一年一年翻，直接问就行。”
项目中的核心任务定义
02 · 产品机会

为什么不继续卷 AI 自动记账？

语音、OCR、自动分类、自然语言查询都可以提升记录效率，但只在“记得更快”上竞争，产品差异会越来越弱。

传统记账

记录

钱 → 记录 → 统计。核心目标是把账记下来。

AI 记账

自动化

钱 → 理解 → 自动记录 → 统计。降低输入成本，但仍围绕交易。

本项目

记住

钱 → 消费 → 记录 → 记忆 → 追踪 → 行为理解。把“交易”变成长期可调用的消费记忆。

产品定位
让竞争维度从 更高效地记录 转向 更有意义地记住。
这不是在给记账增加更多入口，而是在重新定义“记账之后还能发生什么”。
03 · 产品决策

产品决策：意图优先，而不是功能菜单

用户通常不会想着“我要打开记账功能”，而是直接表达任务。Agent 负责把自然语言转化成可执行的工作流。

用户表达“咖啡35”
理解意图记账 / 查询 / 修正 / 分析
读取上下文历史记录与会话上下文
选择工具检索 / 更新 / 调度
判断边界置信度 / 歧义
执行或询问执行 / 澄清 / 确认
最小闭环

记账 → 记忆 → 检索 → 追踪 → 洞察

把 P0 主线收敛成一条可验证的纵向闭环，而不是把所有 AI 能力都放进最小版本。

运行形态

Demo 阶段选择飞书 CUI

低触达摩擦，原生承载语音、图片、文件和群共享；复杂分析展示可以通过文档辅助。

04 · Agent 设计

Agent 不是一个聊天框

Agent 能力从具体任务中的理解、推理、规划、记忆和工具缺口反推，而不是从“用了哪个模型”来定义。

AGT-01 · 意图理解与编排理解语音 / 文字 / 图片 / 文件，拆分多笔消费，分类并生成待确认结果。
AGT-02 · 消费记忆检索从消费数据库检索相关消费，并结合上下文组织答案。
AGT-03 · 主动追踪与状态管理基于触发条件进入追踪状态，发送主动消息并处理回答与不回答。
AGT-04 · 模式分析与边界控制检查数据充分性，再决定是否允许进行模式推断。
AGT-05 · 上下文与指代消解处理“那个 / 那笔 / 上次买的”，并根据候选结果决定直接执行还是请求用户澄清。

05 · 信任与边界

当 Agent 不确定时怎么办？

这是整个项目中最核心的 Agent 交互问题之一：不猜、不越权、保留用户最终控制权。

1 个候选

唯一匹配
继续执行。Agent 有足够证据定位到目标。

≥2 个候选

多候选
展示候选并请求用户选择，不擅自猜测。

0 个候选

无匹配
停止自动执行，请用户补充信息。

一个很典型的 Agent 问题
“把那个改成在用。”
Agent 会按时间、品类 / 关键词、金额、商户、上下文等维度定位记录。最终得到的不是一个普通“搜索结果”，而是一个需要考虑不确定性的产品决策。
人在回路中

高风险动作不交给 Agent 猜

未经确认不入账；删除与恢复有二次确认；多候选需要用户选择。

证据优先

置信度最终要落到行为

不是为了展示一个漂亮百分比，而是决定“执行、确认还是澄清”。

06 · 核心场景

5 个最值得展示的 Agent 场景

我没有平均展示所有功能，而是挑出最能证明 Agent 能力的五条端到端路径。

01 · 输入意图 + 置信度

自然语言记账

理解、拆分、分类、置信度判断，直到用户确认后才真正入账。

“咖啡35，吃饭50，外卖30”
→ 3 笔待确认记录
02 · 记忆检索

消费记忆检索

不靠用户翻流水，而是直接问自己的消费历史。

“我上次买积木是什么时候？”
→ 返回时间、金额、关联状态
03 · 歧义0 / 1 / 多

模糊指令

识别“那个、那笔、上次买的”，并根据候选数量决定执行还是澄清。

“把那个改成在用”
→ 多候选时请求选择
04 · 主动性调度 + 状态

买后主动追踪

30 天后主动询问使用状态，未回答时只补问一次，然后停止打扰。

“这个相机配件，现在还在用吗？”
05 · 洞察证据边界

消费模式分析

先判断数据是否足够，再决定是否允许模式推断。

事实展示 ≥1 笔；同类 ≥3 笔才允许模式推断。

为什么“记忆”才是产品核心

记账只是输入。真正持续产生价值的，是这些信息能够在未来被重新调用。

消费记忆

08 · Agent 评测

我怎么知道 Agent 做对了？

把“设计判断”进一步转化为可重复测试的 Agent 评测。

评测闭环

原子案例 → 测试数据 → 正确行为 → 试跑 → 评分

题目和判法分开，避免 Agent 在试跑前看到自己的答案，也让每一次差异都有明确的判定依据。

示例 · AC-04

指代消解

同一句“把那个改成在用”，分别构造 0、1、≥2 候选，验证 Agent 是否正确处理不确定性。

结果用户目标是否完成
对话用户实际看到了什么
过程内部发生了什么：检索、匹配、工具调用
状态权威状态如何变化
真实动作外部动作是否真实发生
最终判定通过 / 有差异 / 受阻 / 未评测，并单独检查红线

13 · 复盘

如果继续做，我会先验证三件事

把下一阶段的工作从“继续加功能”转向“验证核心价值”。

01

用户愿不愿意长期维护消费记忆？

记录有即时价值，但买后追踪属于延迟价值。需要验证用户是否愿意持续参与。

02

主动追踪是不是价值，还是打扰？

Agent 越主动不代表体验越好，需要验证相关性、时机与频率之间的平衡。

03

用户是否真的认同“消费记忆”？

最终要证明产品不是“更聪明的记账工具”，而是一套值得长期留下来的个人消费记忆系统。
